# Deployment runbook

**State:** the owner created the private `martonkadi/poker-practice` GitHub repository. Scripts and a Cloudflare dry-run are prepared; no Supabase, Cloudflare or Google provider account has been connected, so no production URL, live migration, or Google sign-in verification exists. Keep the GitHub repository private. Use only GitHub included Actions, Supabase Free, Cloudflare Free, and a Google Cloud OAuth project with no paid services.

1. Attach the existing local Git `main` to the owner's empty, private `https://github.com/martonkadi/poker-practice` repository and push. Configure main branch protection where available: require the `check` and `database` CI jobs, no required second human reviewer, squash merging, and delete merged branches. Disable paid Actions overage. Implement each remaining milestone on `feat/mN-description` with a PR and evidence in `PLAN.md`; do not tag `v0.1.0` until all acceptance gates pass.
2. Create a Supabase **Free** project. Record its project ref, URL, and publishable key. Configure Google Auth as the only browser sign-in method; disable email/password sign-up in the dashboard. The migration also rejects non-Google enrollment by default. In Google Cloud create a Web OAuth client. Set its authorized origin to the final Cloudflare `workers.dev` origin and its authorized redirect URI to Supabase’s exact `/auth/v1/callback` URL. Add the Google client ID/secret only to Supabase’s Google provider configuration. Set Supabase Site URL and redirect allow-list to the exact production origin and `/auth/callback` route.
3. Create a Cloudflare Free account and retain the default `workers.dev` hostname. Create a narrowly scoped API token for deploying this Worker and note the account ID. Do not buy a domain or enable a paid plan.
4. Add GitHub **production environment secrets** named `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, and `SUPABASE_DB_PASSWORD`. Add environment variables `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. Never put service-role or OAuth secrets in a `VITE_` variable. The workflow sets `VITE_APP_ENV=production` and embeds the Git commit in About.
5. Run CI on the PR and merge only after `pnpm check`, Chromium, PokerKit, and local database tests pass. Trigger `.github/workflows/deploy.yml` manually from `main`. It checks configuration, runs `pnpm check`, links Supabase, applies migrations, deploys the authenticated `delete-account` Edge Function, builds the web app, then runs `wrangler deploy`. Migrations must remain backward compatible while prior frontend deployments can still be served. Do not automatically roll back a database migration.
6. Verify the actual `workers.dev` URL: guest complete hand; direct `/review/:handId` and `/history` navigation; Google sign-in and callback; explicit guest import choice; completed-hand cloud sync; a second device's retained history; account deletion. Check browser devtools for absent privileged secrets. Record the commit, bot versions, URL, tests, and browser/OS in `docs/acceptance.md`.

Preview deployments must omit both Supabase browser variables so each preview is guest-only; do not permit a preview URL in production OAuth redirects. To roll back frontend code, deploy the previous known-good Git commit with the same static workflow and confirm direct routes and guest play. Review database compatibility first; never reverse a destructive migration automatically.

Locally, `pnpm build` creates `dist/` and `pnpm exec wrangler deploy --dry-run` validates the static bundle without provider credentials. See [operations](operations.md) for quota controls and pause behavior.
